How the page talks to the platform

Three protocols, one request path. Each line below is a real network call.

  1. Browser to Gateway
    REST + SSE

    The page calls /api/flights and listens to a live feed on /api/telemetry/stream.

    curl localhost:8080/api/flights
  2. Gateway to Flight service
    gRPC

    Typed calls fetch flights. A server stream pushes one position update per second per aircraft.

    grpcurl -plaintext localhost:9090 list
  3. Gateway to Booking service
    SOAP

    Bookings travel as XML envelopes described by a WSDL contract.

    curl localhost:8081/ws/bookings.wsdl
  4. Booking service to PostgreSQL
    JDBC

    Every ticket is stored in a database that lives in a Docker volume, so it survives restarts.

    docker compose exec postgres psql -U skyport -c "select * from bookings"
SkyPort is a demo platform. All flights are simulated.
